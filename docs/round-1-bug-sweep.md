# Findings 1–17: verification and fixes

Twelve findings led to fixes, including two with qualified explanations. Five did not reproduce against the current implementation and supported rendering paths. Prior round-2 fixes were preserved.

| Finding | Verdict | Evidence and action |
| --- | --- | --- |
| 1: static face-SDF axes | Confirmed | Face forward/right are now mesh-local bind-space directions. The vertex shader applies the weighted skin matrix and model matrix before the fragment shader computes the light angle. Object turns and animated head motion therefore affect the face basis. |
| 2: unskinned world normal | Not present in current code | `skinnormal_vertex` runs before the world-normal assignment. In the installed Three.js version it modifies `objectNormal` directly. The report's statement that it only modifies `transformedNormal` is incorrect. No change was made for this claim. |
| 3: missing mirrored SDF sampling | Confirmed for symmetric half-face maps | Symmetric mode now mirrors UV.x with light side and uses the absolute angle for a shared threshold. Different texture conventions are not interchangeable: `faceSdfMode: 'signed'` retains the previous signed-angle sampling. The report's claim that both sides always produced identical output was overstated; the old thresholds already differed by sign. |
| 4: packed RGBA depth fallback | Not present in supported path | The pipeline explicitly creates a `DepthTexture` using `DepthFormat` and `UnsignedIntType` and passes that attachment to the atmosphere pass. It does not supply an RGBA-packed color attachment or implement the claimed automatic packing fallback. |
| 5: reversed/logarithmic depth | Unsupported configuration, not a reproduced bug | `Viewport` does not enable these modes, and the shader is used with standard perspective depth. Supporting other depth conventions requires a coordinated pipeline change; no alternate depth mode was added here. |
| 6: resolution compounding on re-enable | Not reproduced with existing profiles | `disable()` already calls `applyLevel(0)`, restoring scale 1 before the next `enable()` captures the baseline. A regression test performs three complete degradation/disable/re-enable cycles and verifies the original pixel ratio each time. |
| 7: manual telemetry bypasses cooldown | Confirmed | Manual FPS updates and internal samples now use the same clock and quality-adjustment method, including cooldown checks and transition timestamps. Non-finite or negative telemetry is ignored. |
| 8: duplicate engine sampling loop | Not present in current integration | The internal animation-frame loop samples the scaler; neither `Viewport.render()` nor the engine loop also calls its `update()` or `sample()`. Consumers should not independently drive the manual sampler while using automatic sampling. No nonexistent engine call was removed. |
| 9: missing LOD skeleton binding | Related bug confirmed, proposed cause incorrect | `SkinnedMesh.clone()` already copies its skeleton and bind matrices; calling `bind()` on the same source skeleton would not fix ownership. The actual problem was that cloning the hierarchy left meshes referencing the source bones. LOD creation now uses `SkeletonUtils.clone`, shares the cloned rig across levels, preserves animated transform/morph targets through an anchor, handles root meshes, and avoids mutating a hierarchy during traversal. |
| 10: stride decimation punches holes | Confirmed | Replaced triangle dropping with meshoptimizer edge-collapse simplification. Group borders are locked and material groups are rebuilt. A requested ratio may not be attainable within topology and error constraints. Closed-mesh edge-count tests verify no holes are introduced on the regression fixture. |
| 11: non-indexed meshes skipped | Confirmed | Non-indexed geometry is welded across compatible vertex attributes and indexed before simplification. Non-indexed morph geometry keeps distinct vertices to avoid merging different morph states; such constraints can limit reduction. Skin, morph, UV and other vertex streams retain their correspondence. |
| 12: hierarchy bounds ignore transforms | Confirmed | Bounds now transform each geometry box with the mesh's current world matrix, including parent transforms, offsets, rotations and scale. The returned bounds are documented as world-space bounds. |
| 13: metadata-only texture downscale | Confirmed | Supported DataTextures receive smaller typed pixel arrays; decoded image textures are resampled into a separate canvas. The derived texture receives its own `Source` and stale mip levels are cleared. Unsupported formats/environments retain the real source dimensions and report `optimizationSkipped` rather than fictitious savings. The original texture is deliberately retained and unmodified. |
| 14: cumulative animation reduction error | Confirmed | Quaternion and vector reduction now validate every original key in each proposed replacement span and split at the largest error. Quaternion comparisons use normalized SLERP. Discrete, smooth and cubic-spline layouts are preserved instead of treating them as linear curves. The tolerance is checked at original key times; it is not a formal continuous-time angular-error guarantee. |
| 15: animation LOD loses elapsed time | Confirmed | Per-instance elapsed time accumulates across skipped updates and is passed to the mixer on the next update, including when distance tiers change. Distance is measured in world space. |
| 16: equivalent settings miss cache | Confirmed, with terminology correction | JavaScript property enumeration is deterministic, but insertion order differs between equivalent objects. Cache settings are now recursively canonicalized by sorted object keys while retaining array order. Cyclic and non-JSON settings are rejected explicitly. |
| 17: unbounded cache retention | Confirmed | Added LRU retention limits: 256 MiB of declared entry sizes and 256 entries by default, both configurable. Hits update recency; oversized variants are not retained. Metadata copies protect accounting from caller mutation. Eviction drops cache references and optionally notifies the resource owner; it does not dispose assets that a live scene may still use. |

## API and ownership notes

- `MeshOptimizer.optimizeGeometry()` and `createObjectLOD()` now return promises. Await them. Both existing repository callers were updated.
- The already-installed meshoptimizer 0.18.1 package is now an explicit runtime dependency. Its [documented WebAssembly readiness requirement and simplification semantics](https://github.com/zeux/meshoptimizer/blob/master/js/README.md) explain the asynchronous API. No top-level await is required.
- Pass an entire character hierarchy, including all referenced bones, to `createObjectLOD()`. A partial skeleton hierarchy produces an explicit error instead of an invalid cloned rig.
- Partial draw ranges or material groups that do not partition the index buffer are conservatively retained and marked `simplificationSkipped`.
- Texture resampling preserves the original source. DataTexture resampling uses pixel-center nearest sampling, preserving integer and half-float encodings. Canvas image resampling uses the browser's image filter. Compressed, depth, cube, video and render-target textures are not resampled by this helper.
- Cache limits constrain retained entries and their declared sizes, not all process/GPU memory. Referenced runtime assets remain owned by their consumers. `onEvict` is a notification hook for ownership-aware cleanup, not permission to dispose an asset still in use.
- Symmetric SDF maps now default to mirrored sampling. Use `faceSdfMode: 'signed'` for assets authored to the old signed-threshold convention.
